# attribution/ — PnL explain + bucketed curve risk (Research OS R15 / R22 local basis / R23 units-roll fix)

## Purpose
Turn "explain why this makes money" from prose into a **quantitative attribution**. Given a replay run record (R12) + the curve (R10), decompose the realized PnL into **level / slope / curvature / carry / residual**, and compute the **bucketed curve risk** on the positions. This is the quantitative form of §10's "name which of the three edges": mostly **carry** ⇒ a harvested risk premium; mostly **slope/curvature** ⇒ a structural relative-value normalisation; a large **residual** ⇒ unexplained — a red flag for noise / overfit.

## Units / roll discipline (R23 — the correction that makes residual mean what the governance layer assumes)
R15's components were always in **return units** (a `÷Pp` divide), so they reconcile to a run whose `stepPnl` is `position·return` (R15's own tests + the generic R12 replay). But the **R16–R21 strategy templates book DOLLAR PnL** (`position·ΔP`, net of costs); attributed in return units, the components came out `~1/Pp` too small and the residual absorbed almost the whole PnL — **residual-dominated by a UNIT MISMATCH, not by basis or noise** (a large part of R20's 1.06; skill #27). R23 makes the decomposition **units-aware**: it attributes in the **same units as the run's realized PnL**.
- `.attribution.__resolveUnits[run]` decides dollar-vs-return per run: an explicit `` `units `` key on the run/meta or `.cfg.attribution.defaultUnits` wins; otherwise it **infers** by comparing the run's booked price PnL to the reconstructed dollar-vs-return gross (the `~Pp` factor makes single-contract records unambiguous; a legs record aggregates the evidence across **all** legs; a strict tie defaults to **return** — the historical path).
- **DOLLAR** runs attribute price-unit components (no `÷Pp`); **RETURN** runs keep the original `÷Pp` path **byte-identically** (R15's known-answers + R22's return-booked synthetics are unchanged to the last bit, verified new-vs-old).
- **Roll routing:** a roll (the difference-method contract switch) is **not a curve move**, so on `isRoll` the booked `positionPnl` is the **carry** component and level/slope/curvature are 0 — a roll never books a phantom curve move into residual. Both branches are additive (records without `units`/`isRoll`/`positionPnl` take the original path). The R12/R13 cores + the strategy templates + how they book PnL are **unchanged**.

## Modules
- `attribution.q` — `.attribution.*`: the PnL decomposition + the bucketed risk.

## Key API
- `.attribution.pnl[run]` → `` `level`slope`curvature`carry`residual`total`residualFraction`reconciled ``. Per step, the active contract's price change splits as `P_t(τ_t) − P_{t-1}(τ_{t-1})` = **carry** (the roll-down along the *current* curve as the contract ages, `P_t(τ_t) − P_t(τ_{t-1})`) + the **curve shift** at the fixed tenor (`P_t(τ_{t-1}) − P_{t-1}(τ_{t-1})`). The shift is projected onto R10's parallel/slope/butterfly shapes (normal equations) → **level/slope/curvature**; the part the basis does not span is the curve residual. `residual` is **defined** as `realizedStepPnL − (level+slope+curvature+carry)`, so the five **always reconcile** to the realized total (it also absorbs costs/financing). `residualFraction = |Σresidual| / |total|`.
- `.attribution.risk[run]` → the bucketed curve **delta** per tenor (the end position's $ sensitivity to a unit move per maturity bucket), the **roll-down exposure** (position × the end curve's `rollYield`), and the **calendar-spread exposure** on the end-of-run position.
- **(R22) `.attribution.pnlLocal[run]`** → the same `` `level`slope`curvature`carry`residual`total`residualFraction`reconciled `` (+ a `` `basis `` tag), but the level/slope/curvature shapes are fit to a **LOCAL window of the curve around the traded tenors** (the traded-tenor sub-curve when ≥3 distinct; a padded contiguous window otherwise) rather than the whole curve. Localized structure (e.g. a near-curve butterfly's curvature, which the *global* bow — peaking mid-curve — cannot see) attributes to the local component, so its residual is the genuine idiosyncratic part. **The global-basis `.attribution.pnl` is byte-identical — this is a NEW mode**, not a change. **The honesty safeguard:** the local basis is still only **THREE fixed factors** (not one per contract), and the window has more points than factors (overdetermined), so a genuine high-frequency / idiosyncratic move is **not** spanned and keeps a HIGH local residual — the local factors *recover* residual's diagnostic meaning, they do not destroy it.
- **(R22) `.attribution.residualSplit[run]`** → `` `globalResidualFraction`localResidualFraction`verdict ``: reports both residuals and classifies — **HIGH local** = genuine idiosyncratic noise (the real red flag); **LOW local + HIGH global** = localized real structure the global basis missed (the R20 butterfly case); both low = well explained.
- **(R23)** `.attribution.pnl` / `.attribution.pnlLocal` are now **units-aware** (see *Units / roll discipline* above): on a **dollar-booked** run they reconcile to `position·ΔP` and the residual is honest (no `÷Pp` artifact), and R22's local basis now does its job on the **dollar runs real strategies produce**, not just return-booked synthetics. `.cfg.attribution.defaultUnits` (`` `infer ``, or force `` `dollar ``/`` `return ``) controls the convention. The re-attribution sweep `apps/examples/reattribution_sweep.q` re-runs R16–R21's replays and prints the true residual fractions beside the previously-reported (units-distorted) ones.

## Notes (the careful-reviewer points)
- **Reconciliation** — `level+slope+curvature+carry+residual == realized total` within `.cfg.attribution.reconcileTol` (like R13's `pnlTies`); the residual is the plug. The non-trivial tests are: a **pure parallel** move → `level` (residual ≈ 0); a **pure slope** move on a *deferred* position → `slope` dominates (R10's slope/curvature shocks pivot on the front, so a front-only position has ~0 slope/curvature exposure by construction); a **pure roll-down** on a tenor-static backwardated curve → `carry`; an **out-of-basis** (zigzag) move → a **high residual fraction**.
- The residual lumps together everything the basis does not span (a basis-spread or inter-commodity move lands in residual) — a large residual is "unexplained", which may be noise **or** a real unmodelled factor, so interpret with care. The carry attribution depends on R10's `rollYield` definition. Inter-commodity basis exposure is out of scope for a single-commodity run.
- The attribution **feeds the model card's economic-rationale with numbers** — but auto-populating a card from it is a *consumer* concern (R16's strategy card), so `cards/` is **not** rewired here; the capability is provided + documented.
- Reserved-name discipline: `asOf` not `asof`, `comm` not `commodity`; builtins (`lsq`/`mmu`/`inv`/`sum`/`avg`/`first`/`last`/`bin`) not shadowed; the basis is derived **from** R10's shock operators (not reinvented). Mind the backtick-index precedence: `(t)\`price - px` parses as `t[\`price - px]` — write `((t)\`price)-px`.
- Demo: `apps/examples/pnl_attribution.q` (real CRUDE: the level/slope/curvature/carry/residual split + the residual fraction + the bucketed risk; reconciles to the realized total).
